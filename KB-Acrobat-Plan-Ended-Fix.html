Acrobat shows "Your plan ended" for a licensed user

How to clear cached Adobe sign-ins and switch Acrobat to browser-based sign-in on Entra-joined Windows devices, so the user lands on their Mountainside enterprise license.

Applies to: Adobe Acrobat (Enterprise / VIP), Windows 10 and 11 Time: about 10 minutes Requires: local admin for step 3

Symptoms

A user with an assigned Acrobat license opens Acrobat and sees "Your plan ended," "trial expired," or a prompt to subscribe. Premium tools such as Edit, Export, and Organize are locked. Signing out and back in does not help, or the issue returns after a few days.

Cause

Acrobat's built-in sign-in window (CEF) does not pass the device ID that Entra ID Conditional Access expects, so the enterprise sign-in can fail or fall back to a different Adobe account. When the user also has a second Adobe account (for example a personal or cloud-only Adobe ID alongside the Mountainside Federated ID), cached credentials in Windows Credential Manager keep pointing Acrobat at the account without a license. Clearing those credentials and forcing sign-in through the system browser resolves it.

Resolution

1
Signed-in user session

Close every Adobe app

Quit Acrobat and the Creative Cloud desktop app if present, including from the system tray. To be sure nothing is still running, open PowerShell and run:

Get-Process Acrobat,AcroCEF,AcroRd32,AdobeCollabSync,AdobeIPCBroker,"Creative Cloud",CCXProcess,CCLibrary,CoreSync,"Adobe Desktop Service" -ErrorAction SilentlyContinue | Stop-Process -Force
2
Signed-in user session, not elevated

Clear cached Adobe credentials

Open a regular Command Prompt as the affected user and run the command below. It removes every Credential Manager entry whose name contains "Adobe App".

for /F "tokens=1,* delims= " %G in ('cmdkey /list ^| findstr /c:"Adobe App "') do cmdkey /delete %H
Credential Manager is per user. If you run this from an elevated prompt under your own admin account, it clears your credentials, not the user's. Run it in the user's own session.

If you prefer PowerShell, this does the same thing:

cmdkey /list | Where-Object { $_ -match '^\s*Target:\s*(.+Adobe App .*)$' } | ForEach-Object { cmdkey "/delete:$($Matches[1].Trim())" }
3
Local admin

Set Acrobat to sign in through the system browser

Using Registry Editor (Win + R, type regedit, select OK):

  1. Go to HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Adobe\Adobe Acrobat\DC\FeatureLockDown. If FeatureLockDown does not exist, create it as a new key.
  2. Inside FeatureLockDown, create a new DWORD (32-bit) Value named iAcroLoginType.
  3. Set its value to 5.
  4. Close Registry Editor.

Or run this from an elevated Command Prompt or PowerShell. It writes the value to both the 64-bit and 32-bit registry views so it works for either Acrobat build:

reg add "HKLM\SOFTWARE\Policies\Adobe\Adobe Acrobat\DC\FeatureLockDown" /v iAcroLoginType /t REG_DWORD /d 5 /f /reg:64
reg add "HKLM\SOFTWARE\Policies\Adobe\Adobe Acrobat\DC\FeatureLockDown" /v iAcroLoginType /t REG_DWORD /d 5 /f /reg:32
4
Signed-in user session

Relaunch Acrobat and sign in

Open Acrobat. Sign-in should now open in the default web browser instead of a pop-up window. Have the user enter their @mountainside.com address and choose Company or School Account if asked, then complete the Microsoft sign-in.

Confirm the fix

In Acrobat, select the profile icon in the top right and confirm the signed-in email is the user's Mountainside address. The "Your plan ended" panel should be gone and Edit, Export, and Organize should open without a subscribe prompt. To confirm the registry value from PowerShell:

Get-ItemProperty "HKLM:\SOFTWARE\Policies\Adobe\Adobe Acrobat\DC\FeatureLockDown" -Name iAcroLoginType

If it still fails

Adobe documents two fallbacks for the same Conditional Access issue. Try them in order, relaunching Acrobat after each.

FallbackChange
AIn the same FeatureLockDown key, add DWORD iNGLCEFWorkflowEnabled with value 0.
BCreate an empty file named EnableIEBrowserWF.CONFIG in C:\ProgramData\Adobe\OperatingConfigs (create the folder if missing).

If the user still lands on the wrong account, check the Adobe Admin Console for duplicate entries under different identity types (Adobe ID and Federated ID) and escalate to Adobe Enterprise Support to reconcile them.

Fleet-wide option

For multiple devices, the same fix is available as Intune scripts: a device script (runs as SYSTEM, sets the registry value), a user script (runs with the logged-on user's credentials, clears Credential Manager), and an optional Remediations detection script to keep the value in place after Acrobat updates. Ask the endpoint team for the package.
